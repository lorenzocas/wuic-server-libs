FlottaMezzi

Applicazione WUIC per la gestione completa di una flotta di veicoli aziendali — anagrafiche, manutenzione, rifornimenti, scadenze documentali, geolocalizzazione e reportistica.

Panoramica#

FlottaMezzi è un'applicazione costruita sul framework WUIC (metadata-driven) che copre l'intero ciclo di vita di un parco mezzi:

  • Anagrafiche di mezzi, conducenti, contratti assicurativi.
  • Operatività quotidiana: registrazione rifornimenti, manutenzioni, revisioni periodiche, sinistri.
  • Monitoraggio scadenze: patenti, assicurazioni, revisioni — con notifiche bell e alert visivi.
  • Geolocalizzazione dei mezzi su mappa Google Maps con tracciamento posizione storica e polyline percorso.
  • Reportistica e dashboard analitiche (aging scadenze, forecast costi, classifica mezzi per costo/km).
  • Multi-ruolo: admin, gestore flotta, autista, meccanico, sola lettura.

Avvio rapido#

  1. Verificare che esistano i due database FlottaMezzi_Metadata e FlottaMezzi_Data sull'istanza SQL Server configurata.
  2. Avviare il backend: dotnet run da C:\src\Wuic\FlottaMezzi.
  3. Avviare il frontend (dev): npm run serve:npm da C:\src\Wuic\FlottaMezzi\wwwroot.
  4. Aprire http://localhost:4200 e fare login con admin / admin (o uno degli utenti seed di test).

Configurazione — appsettings.json#

I file di configurazione principali sono:

FileQuando si usa
appsettings.jsonBase, caricato sempre. Contiene valori di default.
appsettings.Development.jsonOverride per ambiente Development (locale). Mai committare segreti reali.
appsettings.mssql.json / appsettings.mysql.jsonOverride per provider DBMS specifico.

Connessioni database

Sotto la sezione ConnectionStrings:

"ConnectionStrings": {
  "MetaDataSQLConnection": "Data Source=localhost\\sqlexpress;Initial Catalog=FlottaMezzi_Metadata;User ID=sa;Password=***;Encrypt=False;TrustServerCertificate=True",
  "DataSQLConnection":     "Data Source=localhost\\sqlexpress;Initial Catalog=FlottaMezzi_Data;User ID=sa;Password=***;Encrypt=False;TrustServerCertificate=True"
}
  • MetaDataSQLConnection: DB metadati. Contiene route, dashboard (dom_board), tabelle e colonne metadata WUIC, utenti, ruoli, scheduler, menu.
  • DataSQLConnection: DB dati applicativi. Contiene le tabelle business (mezzi, conducenti, manutenzioni, ecc.) e le view di aggregazione per le dashboard.
⚠ Convenzione importante
Non scambiare i due DB: tabelle business solo su FlottaMezzi_Data, metadata WUIC solo su FlottaMezzi_Metadata.

Google Maps API

La sezione GoogleMaps in appsettings.json:

"GoogleMaps": {
  "ApiKey": "AIzaSy...la-tua-chiave..."
}

La chiave deve avere abilitate le seguenti API nel Google Cloud Console:

  • Maps JavaScript API — rendering della mappa + marker e polyline.
  • Routes API — snap-to-roads dei percorsi GPS (sostituisce DirectionsService deprecata).
  • Directions API (fallback) — usata se Routes API non disponibile.
💡 Tip
Per dev locale puoi limitare la chiave a localhost:4200 e localhost:5000 nelle restrizioni HTTP referrer.

Scheduler interno

Il framework gestisce job ricorrenti tramite la tabella dbo.scheduler sul DB metadati (non Quartz/Hangfire/BackgroundService). FlottaMezzi seeda 2 job:

JobOraTipoAzione
flottamezzi_check_scadenze 07:00 ogni giorno HTTP (2) POST /api/flotta/CheckScadenze — scan patenti/assicurazioni/revisioni in scadenza < 30gg, enqueue notifiche bell al gestore_flotta.
flottamezzi_aggrega_costi 02:00 ogni giorno HTTP (2) POST /api/flotta/AggregaCosti — rigenera vista vw_costi_per_mese usata dalla dashboard forecast.

Per disabilitare temporaneamente un job: UPDATE dbo.scheduler SET enabled=0 WHERE event_name='flottamezzi_check_scadenze'.

Setup iniziale di un nuovo ambiente

  1. Creare i DB SQL: CREATE DATABASE FlottaMezzi_Metadata, CREATE DATABASE FlottaMezzi_Data.
  2. Eseguire lo script di clone metadati (da metadataDB template) — vedi skills/app-creation/scripts/new-app.ps1.
  3. Applicare gli script DDL in dbms/schema/ in ordine numerico: 01-lookup-tables.sql, 02-anagrafiche.sql, 03-triggers.sql, 04-views.sql, 09_mezzi_posizioni.sql, ...
  4. Seed dati: dbms/seed/seed-data.sql (lookup + esempi) + 09_mezzi_posizioni_seed.sql (storia GPS demo).
  5. Seed ruoli + utenti di prova: scripts/seed-roles-users.ps1.
  6. Seed menu e dashboard: scripts/seed-menu-flotta.sql + scripts/seed-dashboards.ps1.
  7. Seed scheduler: scripts/2026-05-09-scheduler-jobs.sql.
  8. Compilare backend: dotnet build. Compilare frontend: npm install + npm run build.

Permessi metadata

I permessi sono espressi nella tabella _mtdt__tnt__trzzzioni__tabelle (tabella-level) e _mtdt__tnt__trzzzioni__colonne (colonna-level) del DB metadati. Esempio: per il ruolo autista (id_ruolo=19):

UPDATE _mtdt__tnt__trzzzioni__tabelle
SET md_editable=0, md_insertable=0, md_deletable=0
WHERE ruoloid=19
  AND md_id IN (SELECT md_id FROM _metadati__tabelle
                WHERE mdroutename IN ('mezzi','contratti_assicurativi','sinistri'));

Dopo qualunque modifica permessi, invalidare la cache metadata:

POST /api/Meta/AsmxProxy/MetaService.invalidateMetadataRuntime

Conducenti (conducenti)

URL: #/conducenti/list

  • nome, cognome, codice_fiscale (validazione regex 16 char), numero_patente, scadenza_patente, telefono, email.
  • mezzo_assegnato_id: FK al mezzo predefinito (relazione bidirezionale aggiornata da hook L4 Conducenti.cs).

Manutenzioni (manutenzioni)

URL: #/manutenzioni/list

  • mezzo_id, tipo_manutenzione_id (lookup: ordinaria / straordinaria / revisione / gomme), data, km_alla_manutenzione, descrizione, costo, officina, fattura_numero.
  • Hook beforeInsert: valida che km_alla_manutenzione >= mezzi.km_attuali.
  • Hook afterInsert: aggiorna mezzi.data_ultima_manutenzione.

Rifornimenti (rifornimenti)

URL: #/rifornimenti/list

  • mezzo_id, conducente_id, data, litri, costo_totale, prezzo_litro, km_veicolo, distributore.
  • Il prezzo per litro è mostrato in lista come €/L (carattere euro UTF-8).
  • Trigger DB tr_rifornimenti_aggiorna_km aggiorna mezzi.km_attuali al massimo km_veicolo per il mezzo.

Contratti assicurativi (contratti_assicurativi)

URL: #/contratti_assicurativi/list

  • mezzo_id, compagnia, numero_polizza, data_inizio, data_scadenza, costo_annuo, tipo_copertura.
  • Suggest sul campo compagnia (callback metadata) per autocompletamento basato su contratti esistenti.

Revisioni (revisioni)

URL: #/revisioni/list

  • mezzo_id, data, esito (positivo / negativo / con prescrizione), scadenza_prossima, centro_revisione, costo.

Sinistri (sinistri)

URL: #/sinistri/list

  • mezzo_id, conducente_id, data, descrizione, controparte, costo_stimato, stato_pratica.
  • Trigger DB tr_sinistri_stato_mezzo: all'INSERT di un sinistro, imposta mezzi.stato_mezzo_id a in_riparazione.

Cruscotto#

Home (home)

URL: #/home/dashboard — landing principale dell'app.

Tile 2x2:

  • Bar chart mezzi per stato — view vw_dash_mezzi_per_stato.
  • Pie chart scadenze imminenti — view vw_dash_scadenze_imminenti (UNION patenti + assicurazioni + revisioni < 30gg).
  • Top 10 manutenzioni recenti — lista ordinata per data DESC.
  • Top 10 rifornimenti recenti — lista ordinata per data DESC.

Mezzi sulla mappa (mezzi_mappa)

URL: #/mezzi_mappa/map — archetipo map WUIC.

  • Marker per ogni mezzo con latitudine+longitudine valorizzati. Colore o SVG configurabili per mezzo (vedi Marker mezzi).
  • Click sul marker → infoWindow con targa, modello, conducente assegnato, ultimo aggiornamento posizione.
  • Polyline overlay: traccia il percorso di ogni mezzo dai punti storici in mezzi_posizioni (raggruppati per mezzo_id, ordinati per timestamp).
  • Snap-to-roads automatico via Google Routes API. Fallback: DirectionsService se Routes non disponibile.
  • Waypoint dots: cerchi cliccabili nei punti GPS originali (pre-interpolazione) — click apre infoWindow con targa + timestamp esatto.
  • Filtro by-bounds disattivato di default (carica tutti i marker). Attivare quando i mezzi superano 200 unità.

Aging scadenze (aging_scadenze)

URL: #/aging_scadenze/dashboard

  • 4 KPI: totale in scadenza 30gg, già scaduti, documenti monitorati, % scaduti (rosso se > 10%).
  • Stacked bar chart per fascia (< 0gg, 0-30, 30-90, 90-180, > 180) stack per tipo documento.
  • Tabella dettaglio: top 20 mezzi con scadenza < 30gg.

View: vw_aging_scadenze, vw_aging_scadenze_per_fascia.

Forecast costi (costi_forecast)

URL: #/costi_forecast/dashboard

  • 2 KPI: costo medio mensile (ultimi 12 mesi), costo proiettato 90gg.
  • Line chart storico ultimi 18 mesi (vw_costi_storici_mensili).
  • Line chart forecast 3 mesi avanti, tratteggiato (vw_costi_forecast, proiezione lineare).
  • Asse X formattato come MM/yyyy via vw_costi_per_mese.etichetta_mese.

Top mezzi (top_mezzi)

URL: #/top_mezzi/dashboard

  • Bar chart top 10 mezzi per costo (somma manutenzioni + rifornimenti + sinistri anno corrente) — vw_top_mezzi_per_costo.
  • Bar chart top 10 mezzi per km percorsi (delta km_attuali) — vw_top_mezzi_per_km.
  • Tabella detailed: targa, modello, conducente, costo totale, km anno, costo per km.

Automazioni#

Trigger DB

TriggerTabellaEventoAzione
tr_rifornimenti_aggiorna_km rifornimenti AFTER INSERT/UPDATE Imposta mezzi.km_attuali = MAX(km_veicolo) per il mezzo. Marker idempotenza: note='AUTO_GENERATED'.
tr_sinistri_stato_mezzo sinistri AFTER INSERT Imposta mezzi.stato_mezzo_id al lookup in_riparazione.

Pattern: SET NOCOUNT ON, IF NOT UPDATE(...) RETURN, ANSI_NULLS/QUOTED_IDENTIFIER ON al momento del CREATE.

Hook CRUD lato server

File in ProjectData/Crud/. Discovery automatica via reflection (UtilityHost.cs).

FileHookCosa fa
Manutenzioni.cs beforeInsert Valida km_alla_manutenzione >= mezzi.km_attuali. Throw eccezione con messaggio localizzato se fail.
Manutenzioni.cs afterInsert Aggiorna mezzi.data_ultima_manutenzione con la data della manutenzione appena inserita.
Mezzi.cs beforeUpdate Validazione targa + normalizzazione campi geo.

Job schedulati

Vedi Scheduler interno. I 2 job seedati invocano endpoint HTTP del backend stesso (no BackgroundService, no Hangfire/Quartz).

  • flottamezzi_check_scadenze (07:00): scan documenti in scadenza, enqueue notifiche bell al ruolo gestore_flotta.
  • flottamezzi_aggrega_costi (02:00): rinfresca aggregato vw_costi_per_mese usato dalla dashboard forecast.
⚠ Anti-pattern
Vietato introdurre BackgroundService, IHostedService, Quartz, Hangfire o Task Scheduler Windows. Tutti i job devono passare per la tabella dbo.scheduler del DB metadati.

Personalizzazione#

Marker mezzi sulla mappa

Per ogni mezzo è possibile personalizzare l'aspetto del marker sulla dashboard mezzi_mappa.

Opzione 1 — Colore (campo colore_marker)

Inserire un valore HEX (es. #1F77B4, #FF6B35) nel form di edit del mezzo. Il marker viene reso con PinElement Google Maps con quel colore di sfondo.

Opzione 2 — SVG inline o URL immagine (campo svg_marker)

Inserire SVG inline o URL di un'immagine. Esempio SVG inline:

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" width="32" height="32">
  <path d="M5 11l1.5-4.5h11L19 11..." fill="#0d6efd"/>
</svg>

Esempio URL:

https://cdn.example.com/icons/truck.png

Priorità: svg_marker > colore_marker > default (PinElement blu).

💡 Tip
Per icone differenziate per tipo_mezzo, popolare svg_marker dal lookup tipo_mezzo.icona_svg via trigger o hook afterInsert personalizzato.

Stili condizionali nelle liste

Configurabili in _metadati__u_i__stili__tabelle con coppia must_attribute_name (classe CSS) + must_attribute_value (callback JS che ritorna boolean).

Stili applicati di default su mezzi:

Classe CSSCondizione
row-warning (giallo)Patente conducente assegnato in scadenza < 30gg.
row-danger (rosso)Assicurazione o revisione scaduta.

Suggest fields

Campi con autocompletamento da valori precedenti (configurati via mc_suggest_value_callback in metadata):

  • contratti_assicurativi.compagnia — suggerisce compagnie già usate.
  • manutenzioni.officina — suggerisce officine già usate.
  • rifornimenti.distributore — suggerisce distributori già usati.

Operations#

Backup e restore

Backup dei due DB con strategia separata:

BACKUP DATABASE FlottaMezzi_Metadata
  TO DISK = 'D:\backup\FlottaMezzi_Metadata.bak' WITH FORMAT, INIT, COMPRESSION;

BACKUP DATABASE FlottaMezzi_Data
  TO DISK = 'D:\backup\FlottaMezzi_Data.bak' WITH FORMAT, INIT, COMPRESSION;

Restore con override (es. su staging):

RESTORE DATABASE FlottaMezzi_Metadata
  FROM DISK = 'D:\backup\FlottaMezzi_Metadata.bak'
  WITH REPLACE,
       MOVE 'FlottaMezzi_Metadata'     TO 'D:\mssql\FlottaMezzi_Metadata.mdf',
       MOVE 'FlottaMezzi_Metadata_log' TO 'D:\mssql\FlottaMezzi_Metadata_log.ldf';

Dopo il restore, obbligatorio:

  • POST /api/Meta/AsmxProxy/MetaService.invalidateMetadataRuntime per riallineare la cache metadata in memoria.
  • Verificare la nuova projectMetadataVersion via MetaService.getProjectMetadataVersion.

Troubleshooting

SintomoCausa probabileAzione
Mappa vuota / marker non visibili API key Google Maps invalida o Maps JS API non abilitata Verificare appsettings.json → GoogleMaps.ApiKey e abilitazione API nel Cloud Console.
Polyline non si curva sulle strade Routes API non abilitata (snap-to-roads fallisce silenzioso) Abilitare Routes API. In console browser cercare "Routes API" error / 403.
Notifiche bell scadenze non arrivano Scheduler flottamezzi_check_scadenze disabilitato o backend down alle 07:00 SELECT enabled, last_ex_succeded, last_execution FROM dbo.scheduler WHERE event_name='flottamezzi_check_scadenze'.
Modifiche metadata non visibili nella UI Cache metadata runtime non invalidata Chiamare MetaService.invalidateMetadataRuntime dopo ogni patch metadata diretta in SQL.
Trigger DB non aggiorna km_attuali ANSI_NULLS/QUOTED_IDENTIFIER non ON al momento del CREATE TRIGGER Ricreare il trigger preceduto da SET ANSI_NULLS ON; SET QUOTED_IDENTIFIER ON; nello stesso batch.
Caratteri non-ASCII corrotti in dati seed (es. â‚¬/L invece di €/L) SQL script salvato in UTF-8 senza BOM e sqlcmd lo legge come CP1252 Usare PowerShell SqlClient con parametri UTF-16 LE, oppure salvare lo script con BOM (UTF-8-BOM).
